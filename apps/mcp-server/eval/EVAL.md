# Evaluation harness

The measurement apparatus the four research packages (`memory/`, `models/`,
`tokens/`, `rendering/`) are optimized against. Code stays comment-free by
convention; this document carries the reasoning.

## What it measures

An agent is scored on **execution output**, not on the text it writes and not
on how closely its code resembles the reference. The contract: given a
natural-language question, the agent emits Python that uses `tatc` and assigns
the answer to a variable `RESULT`. The harness runs that code in an isolated
subprocess, reads `RESULT`, and compares it to ground truth with a
type-appropriate comparator.

This is the only scoring model that (a) tests the actual "AIfication"
capability — can the model produce correct `tatc` analysis — and (b) handles
scalars, vectors, tables and figures uniformly, because a figure is scored on
the data behind it (polygon geometry, coverage table), never on pixels.

## Ground truth

`ground_truth.json` is **generated by the harness** from the reference
solutions in `solutions/`, not hand-transcribed. Run `build_ground_truth.py`
to regenerate. Values are specific to `tatc==3.5.1` with the pinned TLEs,
`epoch = orbit.get_epoch()`, and the fixed analysis windows in each solution.
Change any of those and the numbers move; that is why the pinned tier fixes
them.

Reference answers (tatc 3.5.1):

| Case | Answer |
| --- | --- |
| Q1 | 9.1977 hr |
| Q2 | 2.9444 hr |
| Q3 | [2.9444, 1.4185, 0.9127, 0.6595, 0.5076, 0.4077] hr |
| Q4 | ground-track swath polygon (WKT) |
| Q5 | 32-point coverage table, 0.9020–3.2951 hr |

## Tiers

- **pinned** — Q1–Q5. Fixed TLEs/epoch/window, deterministic, scored tight
  (2% relative tolerance; polygon IoU ≥ 0.98). The regression benchmark: a
  change to memory/model/token policy either holds these or it does not.
- **live** — the snow-study case. Underspecified on purpose (source the
  TLEs/swath specs, descending-orbits-only, integrate a full year). No fixed
  reference answer, so it is carried as `kind="open"` and left unscored by the
  automated runner; it is the agentic stretch case, evaluated separately.

## Comparators (`compare.py`)

| Kind | Method | Pass condition |
| --- | --- | --- |
| scalar | relative error | ≤ tol (default 0.02) |
| vector | element-wise relative error | all elements ≤ tol; score = fraction passing |
| polygon | Shapely intersection-over-union | IoU ≥ tol (default 0.98) |
| table | join on `point_id`, per-point relative error on `mean_revisit_hr` | same point set and all points ≤ tol; score = fraction passing |

Tolerance is relative, not absolute, so it scales across the 0.4–9.2 hr range.
IoU is used for the polygon because exact WKT match is brittle to vertex
ordering and float noise while IoU is not.

## Per-file I/O map

| File | In | Out | Depends on |
| --- | --- | --- | --- |
| `cases.py` | — | `Case` records; `by_tier`, `get` | stdlib |
| `solutions/Q*.py` | — (pinned params inline) | assign `RESULT` (plain JSON types / WKT) | tatc |
| `sandbox.py` | code string, timeout | `Execution(ok, result, error, seconds)` | stdlib subprocess |
| `compare.py` | got, expected, tol | `(passed, score, detail)` | shapely |
| `adapters.py` | `Case` | code string | `agent.run_task` (baseline only, lazy) |
| `build_ground_truth.py` | `solutions/` | `ground_truth.json` | sandbox, cases |
| `runner.py` | adapter, tier | per-case results + aggregate JSON | compare, sandbox, cases |

## Adapters — the agent under test

`AgentUnderTest` is a structural protocol: anything with `name` and
`solve(case) -> code_string` plugs in. Two ship today:

- `ReferenceAgent` replays the canonical solution. It is the harness's
  **self-test**: it must score 5/5 / mean 1.0, which proves the comparators
  and sandbox are correct before any model is trusted. It does.
- `BaselineAgent` wraps the current `agent.run_task` (Gemini, single-shot
  text). It is expected to score near zero on execution, because the baseline
  pipeline emits prose and cannot produce runnable `tatc` — that is the honest
  control the optimization work has to beat, and it is the concrete evidence
  that "AIfication" of these cases requires code-executing tool use, which
  `ARCHITECTURE.md` currently lists as a non-goal.

A code-emitting agent is added as a third adapter; nothing else changes.

## Sandbox caveat

`sandbox.py` isolates execution in a subprocess with a timeout so a crash or
hang in agent-emitted code is caught and scored as `exec_error`, not a harness
failure. It is isolation for robustness, **not** a security sandbox — it does
not restrict imports or filesystem/network access. Run untrusted model output
only in a disposable environment (the Docker MCP image is the intended host).

## Running

```
pip install -r requirements-eval.txt
python build_ground_truth.py                 # regenerate ground_truth.json
python runner.py --adapter reference         # self-test, must be 5/5
python runner.py --adapter baseline          # honest baseline (needs GEMINI_API_KEY)
```

## Adding work

- New question: add a `Case` to `cases.py` and, for a scored case, a
  `solutions/<id>.py` that assigns `RESULT`; rebuild ground truth.
- New agent: implement `solve(case) -> code` and register it in `runner.py`.
- Cost/quality trade-off: `runner.py` reports per-case latency; join it with
  the token/latency records in `usage.jsonl` (written by `tokens/usage.py`) to
  compare answer quality against logged spend per adapter.
